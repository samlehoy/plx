## Overall Impression

The system-level craft is real and held together end to end — reduced motion, the tier-picker's currentColor mechanism, and zero console/network errors across extensive interaction testing all check out under hard evidence, not just visual impression. The gap is in two specific, fixable places: the tier picker borrowed ARIA-tabs vocabulary without the ARIA-tabs behavior, and several low-opacity label variants (not the base `--color-muted` token fixed in the last polish pass) slip under the AA contrast floor. Neither requires touching the signature components' visual language.

## What's Working

1. **Reduced-motion handling is architecturally correct, not a bolt-on.** `main.tsx` only adds the `.js` class when `!prefers-reduced-motion`; every CSS reveal/opacity rule is scoped under `.js .reveal`. Confirmed live with `prefers-reduced-motion: reduce` emulated: `htmlClassList: []`, `.reveal` elements render at `opacity: 1` with `transitionDuration: 0s` by default — the page renders fully formed with zero JS-dependent invisibility.
2. **The tier picker's `currentColor`/`color-mix` mechanism drives three complete palette inversions off one small rule set**, and it's correct under test: clicking each of the 3 tiers produces exactly the `TIERS` array's ground/ink hex values (`rgb(239,239,238)`/`rgb(13,13,15)`, `rgb(13,13,15)`/`rgb(239,239,238)` inverted, `rgb(228,228,226)`/`rgb(13,13,15)`), with per-tier text contrast measuring 15.25-18.25:1 in every state.
3. **Zero console errors, zero failed/4xx requests, zero broken interactions** across both viewports and a full interaction pass (3 tier clicks, 5 scroll-driven readout checks, 20 Tab presses) — the implementation is functionally solid underneath the visual system.

## Priority Issues

**[P1] Tier-picker tab widget is ARIA-broken.** `role="tablist"`/`role="tab"` demands `aria-selected` per the WAI-ARIA Tabs pattern; this ships `aria-pressed` instead. Confirmed live: all three buttons report `ariaSelected: null`, `ariaControls: null`, no `role="tabpanel"` exists anywhere, all three share `tabIndex: 0` (no roving-tabindex/arrow-key navigation). A screen reader gets ambiguous "tab, not selected" state; a keyboard user tabs through all three individually instead of arrowing between them. **Fix**: either implement the real APG Tabs pattern (`aria-selected`, `aria-controls`-linked `role="tabpanel"`, roving tabindex + arrow keys), or drop `role="tab"`/`role="tablist"` entirely and keep it as a plain `aria-pressed` segmented toggle group — it's functionally closer to a segmented control than tab navigation between persistent panels. → `/impeccable harden`

**[P1] Contrast failures beyond the token already fixed.** The last polish pass fixed the base `--color-muted` token (now 4.92-5.44:1). But several *opacity-reduced* label variants use a separate mechanism (`rgba(239,239,238,.4/.45/.5)` overlays on ink, and an unnamed opacity variant on ground) and fail independently:
   - `.meta`/`.meta-sm` at `rgba(...,.45)` on `bg-ink` ("02 / proof", "Free-text — 19 matched…"): **4.08:1**
   - `.meta-sm` at `rgba(...,.4)` on `bg-ink` ("Match rate · cumulative"): **3.46:1**
   - Match-section field labels ("05 / match", "Tier", "Rule", "When it fires", "ms → s · ±3s window") on `bg-ground`: **3.31:1** — the worst measured pair on the page
   - `.meta.text-signal` module names (`spotify.ts`, `deezer.ts`, etc.) on `bg-ground`: **4.49:1** (borderline fail)

   All AA-fail at the 4.5:1 floor for normal-weight text ≤16px. **Fix**: raise these specific opacity values (not the base token) to clear 4.5:1, or move to solid on-brand colors for text use while keeping the low-opacity look for non-text marks. → `/impeccable harden`

**[P1] Hero secondary CTA pixel-overlaps opaque vinyl artwork at desktop widths.** At 1440×900, the "Try --dry-run" pill's bottom-right corner canvas-samples `rgb(16,16,16)` alpha=254 from the vinyl image directly beneath it. That pill is `bg-transparent` with only an 18%-opacity border and `text-ink` glyphs — where it crosses the disc, border and character edges read as near-invisible black-on-black. Confirmed this doesn't reproduce at 390px (record repositions below the CTA row on mobile). **Fix**: push `hero-record`'s `right`/`bottom` offsets further out at ≥1280px, or give the secondary pill an explicit background. → `/impeccable adapt`

**[P2] The single highest-anxiety question is never answered on-page.** "ARL cookie" appears 3x in the hero copy, `DEEZER_ARL` once in the spec table — always as a bare, unexplained term, with no inline "how to get yours" and no elevation of the trust claim ("local-first · no telemetry" sits in a small footer line) at the install moment where a visitor decides whether to hand a CLI their session credential. **Fix**: add a one-line disclosure (tooltip, footnote, or expandable) at the install CTA. → `/impeccable clarify`

**[P2] Mobile has zero wayfinding.** At 390px, the entire nav (Overview/Convert/Match/Spec/Install) measures 0×0 on every link — no hamburger replaces it, only the logo and install pill remain. On a 7-section page with a 320vh decorative section in the middle, mobile visitors have no way to skip ahead. **Fix**: add a mobile menu, or at minimum a persistent section indicator. → `/impeccable adapt`

## Persona Red Flags

**Jordan (First-Timer)**: Reads "browser sessions, not API keys" and "one Deezer ARL cookie is enough" in the hero, has no idea what an ARL cookie is or how to get one. Nothing on the page defines it before the "Docs" footer link, which previews nothing. Likely abandons at exactly the step meant to feel simple ("Install once. Move everything.").

**Sam (Accessibility)**: Tabs through the tier picker with a screen reader and hears "tab" three times with no reliable selected-state announcement (confirmed `ariaSelected: null` on all three). Separately, the proof-section H2 — JSX `"Free text beats" <br/> "field syntax."` — has no period before the break, unlike every other `<br/>`-split heading on the page (`"Move your playlist."`, `"Four modules."`, `"Pick a tier."`, `"Install once."` all end their first line with a period). Its `textContent` concatenates to `"Free text beatsfield syntax."`, a nonsense compound a screen reader may mangle.

**Casey (Mobile)**: Opens on a phone, nav collapses to logo + install pill only. Can't jump to "Match" or "Spec." Must scroll past ~3.2 screen-heights of the wordless spin stage to reach the tier picker, with nothing textual signaling progress toward useful content.

## Minor Observations

- Every footer link (Github/Npm/Docs) and the primary desktop nav links measure under 44px height (inline text links — a commonly exempted pattern, but flagged since raw numbers were requested).
- `alt="Vinyl record"` on the hero image conveys nothing the surrounding headline doesn't already say; could arguably be empty like its below-the-fold twin (`alt=""`).
- Version pin ("0.1.1 · cli") is `hidden xl:block` — invisible below 1280px, a deliberate content-pruning choice worth knowing isn't always-present.
- "Try --dry-run" implies an interactive action but is a plain anchor scroll to `#convert` — a small verb/behavior mismatch.
- `cramped-padding` detector findings (4 desktop / 3 mobile) are false positives — see Design Specificity Verdict.

## Questions to Consider

1. What if the `DEEZER_ARL` acquisition steps were surfaced right where "Install once. Move everything." appears, instead of the acronym being repeated three times unexplained — is conversion actually gated more by trust than by installation friction?
2. What if `role="tab"`/`role="tablist"` were dropped from the match-tier picker entirely, since it's functionally a segmented toggle group, not navigation between independent persistent panels — would that be a more honest fix than retrofitting the full APG Tabs pattern?
3. What if the 320vh counter-travel spin stage were cut shorter — would proof-to-tier-picker momentum hold up better, or is the sheer scroll distance itself part of the "this is real engineering" brand signal worth defending as-is?
